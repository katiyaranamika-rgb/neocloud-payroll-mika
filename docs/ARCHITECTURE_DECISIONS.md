## Where and how calculations run

`runAll(dataset)` in `src/engine/run.ts` is a pure function: **model → time → absence → US payroll → international → GL → reconciliation → audit**. Absence runs after time because hourly accrual uses hours worked. Payroll runs after absence because leave pay and payouts come from balances. The UI calls `runAll` on load and after every edit, and keeps the original run to show what changed.

## Data model

`Worker` (with `rateHistory` and `locationHistory`, derived `supOrg` and `costCenter`) · `Event` · `TimeEntry` · `RosterRow` (last row wins) · `PayInput` (effective-dated deductions) · `Balance` · `PaySchedule`. Results: `TimeResult` (day trace + weekly regular rate), `AbsenceRow`, `RegisterRow` (pay lines by code), `IntlExpected` / `VendorRow`, `JournalLine`; export: `CompanyImport` (a vendor register routed to one company and transposed), `MappedLine` (worker × pay code → account, side, worktags), `MappingResult` / `UsJournal` (journal plus blocking errors); `PayrollStatus` (7 stages per pay group).

## What I would do differently with more time

- Send the US journal through the real Workday payroll journal connector instead of the simulated Transmit.
- Replace the illustrative international employee deductions with the vendor's real files during the parallel runs.
- Load verified YTD and prior-period history instead of deriving it; add a 401(k) annual limit and catch-up logic.
- Statutory tax tables (federal Pub 15-T, state tables, local taxes, Additional Medicare) behind the same interfaces.
- Shared, audited edits (database + user identity) so reviewers can collaborate on what-ifs.
- Split location worktags by days for intra-period location changes (currently period-end location).
- A component framework and visual regression tests for the UI once dependency installs are available.
